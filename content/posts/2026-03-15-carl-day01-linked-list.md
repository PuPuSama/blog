今天写了链表的两个题，记录一下思路和踩坑。

## 203. 移除链表元素

大概思路就是从头遍历，如果当前节点的下一个节点的值是目标元素，直接跳过它：

```cpp
temp->next = temp->next->next;
```

这个题我卡在了**边界处理**的问题上——当要删除的元素恰好在头节点时，需要单独处理。后来知道了可以引入**虚拟头节点（dummy head）**，这样就统一了操作，不用特殊处理头节点的情况。

还有一个坑：返回结果的时候，需要返回 `dummyHead->next` 而不是原来的 `head`，因为 `head` 本身可能已经被删除了。

另外回顾到 C++ 的内存释放：`free` 是释放 `malloc` 申请的内存，而 `new` 创建的对象需要用 `delete` 来释放。

## 707. 设计链表

这道题涉及到 C++ 面向对象的基础知识，最大的收获是：**别忘了更新 `size`**。增删操作之后如果漏掉 `size++` / `size--`，后续操作的边界判断就全乱了。

这两道题都是比较基础的链表题，主要还是熟悉 C++ 面向对象的语法，以及构造函数和析构函数的使用。下面简要回顾一下。

## 附：C++ 构造函数与析构函数

### 构造函数（Constructor）

构造函数在**创建对象时自动调用**，用于初始化成员变量。函数名与类名相同，没有返回值：

```cpp
MyLinkedList() {
    dummyhead = new LinkedNode(0);
    size = 0;
}
```

当执行 `MyLinkedList list;` 时，构造函数自动执行，完成链表初始化。

### 析构函数（Destructor）

析构函数在**对象生命周期结束时自动调用**，用于释放资源。函数名为 `~类名()`，没有参数和返回值：

```cpp
~MyLinkedList() {
    LinkedNode* cur = dummyhead;
    while (cur != nullptr) {
        LinkedNode* temp = cur;
        cur = cur->next;
        delete temp;
    }
}
```

遍历链表逐个 `delete`，防止内存泄漏。

### 小结

- **构造函数**：对象创建时自动调用，负责初始化
- **析构函数**：对象销毁时自动调用，负责释放资源
