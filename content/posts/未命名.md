class Solution {
public:
    bool isAnagram(string s, string t) {
        int record[26] = {0};
        for (int i = 0; i < s.size(); i++) {
            // 并不需要记住字符a的ASCII，只要求出一个相对数值就可以了
            record[s[i] - 'a']++;
        }
        for (int i = 0; i < t.size(); i++) {
            record[t[i] - 'a']--;
        }
        for (int i = 0; i < 26; i++) {
            if (record[i] != 0) {
                // record数组如果有的元素不为零0，说明字符串s和t 一定是谁多了字符或者谁少了字符。
                return false;
            }
        }
        // record数组所有元素都为零0，说明字符串s和t是字母异位词
        return true;
    }
};

 编写一个算法来判断一个数 `n` 是不是快乐数。

**「快乐数」** 定义为：

- 对于一个正整数，每一次将该数替换为它每个位置上的数字的平方和。
- 然后重复这个过程直到这个数变为 1，也可能是 **无限循环** 但始终变不到 1。
- 如果这个过程 **结果为** 1，那么这个数就是快乐数。

如果 `n` 是 _快乐数_ 就返回 `true` ；不是，则返回 `false` 。

 思路是把每次的结果存到哈希表里，然后判断是否在哈希表里，如果在说明发生了环，就不是快乐数

1. 如果已经对 a 和内层元素去重了，还需要 set<vector<int>> 吗？  
    一般不需要。  
    原因是数组已经排好序，加入答案时三元组顺序是固定的；再加上：
    
    - 外层对 a 去重
    - seen 去重左侧已经出现过的值
    - 内层对当前 nums[j] 去重  
        这样重复答案就已经被消掉了，直接用 vector<vector<int>> 保存结果即可。
2. seen 为什么说能“吞掉”前面重复的补数？  
    因为 seen 是 unordered_set<int>，只记录“某个值是否出现过”，不记录出现了几次。  
    例如 nums = [-2, 0, 0, 2]，固定 a = -2 后：
    
    - 第一个 0 插入 seen
    - 第二个 0 再插入时，seen 里还是只有一个 0
    - 等扫到 2 时，只会因为“前面出现过 0”而匹配一次，不会因为有两个 0 就生成两次 [-2, 0, 2]
3. 为什么内层循环要“先查再插入”？  
    这样 seen 里保存的永远是 j 左边已经出现过的数。  
    也就是说，当前 nums[j] 只会和前面的数配对，不会和自己配对，逻辑更清楚也更正确。
    
4. while (nums[j] == nums[j + 1]) j++; 这一步到底在去重谁？  
    严格来说，它去重的是“当前枚举到的 nums[j]”，不一定非要叫它 b。  
    固定 a 后，当前值 nums[j] 一旦确定，另一个值 c = -a - nums[j] 也就唯一确定了，所以跳过重复的 nums[j]，本质上就是在避免重复三元组。
    
5. 哈希法的内层循环到底在做什么？  
    其实就 4 步：
    
    - 固定一个 a
    - 对当前 nums[j]，计算还缺多少：c = -a - nums[j]
    - 去 seen 里查这个 c 是否出现过
    - 查完后把当前 nums[j] 放进 seen
